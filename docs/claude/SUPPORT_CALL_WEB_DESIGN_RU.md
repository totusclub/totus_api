### Решения в макете

- **Пункт меню** встаёт под «Чат с поддержкой», с подписью «Голосовой звонок» — так человек заранее понимает, чем он отличается от чата.
- **Диалог 420 px** на затемняющей подложке, а не полноэкранный цветной экран: на сайте звонок — не основной сценарий, и человек должен видеть, что страница под ним никуда не делась. Это же решение принято в редизайне панели звонков (`CALLING_REDESIGN_RU.md`).
- **Отдельное состояние «доступ к микрофону»** — в приложении разрешение спрашивает система, в браузере это отдельный шаг, и без него звонок молча не состоится.
- **Состояние «не удалось» — не тупик.** Оператор может быть не на линии (сервер отвечает 404), и вместо сухой ошибки даём три выхода: позвонить ещё раз, написать в чат, телефон. Это тот же принцип, что применили к сценарию «Яндекс не передал email».
- **Свёрнутая плашка** — чтобы во время разговора можно было ходить по сайту.
- Токены — из `DESIGN_SYSTEM_REF_RU.md`: статус разговора `success`, ошибка `error`, кнопка сброса на `error`, подложка `overlay`.

## 3. План реализации (после согласования макетов)

1. `src/api/supportCallApi.ts` — регистрация устройства (`POST /api/register-device`, `voipToken: 'web'`), `POST /api/calls`, `answer`/`candidate`/`end`/`reject`, `GET /api/ice-servers`. Всё через `authFetch` с Bearer, как в `supportChatApi.ts`.
2. `src/lib/supportCallService.ts` — WebRTC: `getUserMedia({audio})`, `RTCPeerConnection` с ICE-серверами от бэкенда, обмен SDP и кандидатами через socket.io (`io(voip, { auth: { token } })`), состояния `idle | permission | calling | answered | ended | rejected | error`.
3. `src/components/support/SupportCallModal.tsx` + свёрнутая плашка, подключение в `_app.tsx` (звонок переживает переход между страницами).
4. `menu.tsx` — вернуть пункт, но уже на настоящий обработчик.
5. Адрес поддержки — `NEXT_PUBLIC_SUPPORT_LOYALTY_ID` (не секрет, но пусть не будет литералом в коде).

## 4. Вопросы к владельцу

1. **Адресат.** Брать тот же loyalty ID, что в приложении (`0978 6356 3712 8057`)? Он один на всю платформу: пока оператор говорит с одним человеком, второй дозвониться не сможет — очереди в сервере нет.
2. **Телефон в макете** `+7 495 123-45-67` — это заглушка из кода приложения. Нужен реальный номер.
3. **Ограничение по `users.access`.** В приложении секция звонка скрыта, если `access !== 0`. Повторять это правило на сайте?
4. **Что показывать, если оператор говорит с другим.** Сервер отвечает одинаково и на «не в сети», и на «занят» — различить нельзя. Сейчас в макете единый текст «Оператор сейчас не на линии».
