# QA-агент Totus — план ежедневного тестирования (RU)

**Статус: план на согласовании, 11.09.2026.** Ничего не создано: ни репозиториев, ни учёток, ни закупок, ни задач на доске. Решения — за владельцем (§12). После утверждения документ кладётся в проект как `claude/QA_AGENT_PLAN_RU.md`, а в оркестраторе появляется **Чат 10 — QA**.

---

## 1. Суть

QA-агент — это Claude Code, который каждое утро сам запускается на выделенном компьютере «QA-стенд» (Mac mini). К стенду по USB подключены настоящие iPhone, iPad и Android-телефоны. Агент проходит сайт, приложения, панель звонков и админку так, как это делает пользователь: нажимает, вводит, листает, делает скриншоты, читает логи. Потом пишет отчёт и заводит баги в GitHub, а короткая сводка приходит в Slack. Владелец разбирает отчёт и отдаёт задачи оркестратору (Чат 0). Код продукта агент не правит никогда: он находит, воспроизводит и перепроверяет исправления.

**Почему Mac mini.** Управлять настоящим iPhone можно только с macOS (Xcode, WebDriverAgent) — то же ограничение, что описано в `CI_IOS_RU.md` §1. Чаты claude.ai к устройствам подключиться не могут: у них нет USB и сети из контейнера. Поэтому «Claude заходит на устройства» технически означает Claude Code на стенде.

## 2. Что агент берёт на себя, а что остаётся людям

| Функция отдела тестирования | Агент | Человек |
|---|---|---|
| Ежедневный регресс критических путей | каждый день, сам | — |
| Проверка после деплоя (smoke) | по команде «проверь релиз» | даёт команду |
| Вёрстка на разных устройствах, тексты, тёмная тема | скриншоты с устройств, сравнение с вчерашними | смотрит спорные случаи |
| Исследовательское тестирование изменённых мест | по коммитам и PR за сутки | — |
| Тест-кейсы и автотесты | пишет флоу, превращает каждый найденный баг в регресс | утверждает список сценариев |
| Перепроверка исправлений | закрывает issue с доказательством или возвращает | — |
| Звонки | установилось ли соединение, экран CallKit, завершение | качество звука, эхо — ухом |
| Оплата реальными деньгами | нет | вручную или на staging |
| Приоритет, «баг или так задумано» | предлагает severity | решает |
| Юзабилити, ощущение продукта | замечания | решение |

Честная рамка: агент закрывает повторяемую и объёмную часть работы отдела. Суждение, деньги и звук остаются у человека.

## 4. Устройства — три уровня

### 4.1 Уровень A — своя мини-ферма на стенде (каждый день)

| # | Устройство | Зачем |
|---|---|---|
| 1 | Mac mini (Apple Silicon) | «мозг» стенда: Claude Code, Xcode, браузеры, desktop-приложение; попутно может стать self-hosted раннером для iOS-сборок (`CI_IOS_RU.md` §4) |
| 2 | iPhone с актуальной iOS | основной iOS-сценарий, пуши, CallKit |
| 3 | iPhone компактный или на iOS постарше | маленький экран, старая система |
| 4 | iPad | планшетная вёрстка (фаза P6) |
| 5 | Samsung Galaxy A-серии | самый массовый Android в РФ |
| 6 | Xiaomi / Redmi бюджетный | слабое железо и агрессивное энергосбережение, которое убивает фоновые процессы — критично для звонков |
| 7 | Huawei / Honor без Google-сервисов (опционально) | без FCM пуши и входящие звонки не придут — нужно понимать, как приложение себя ведёт |

Для звонков и чата поддержки пара уже есть: панель агента в браузере стенда + телефон. Устройства б/у подходят.

**Обслуживание.** Телефоны круглосуточно на зарядке — нужны умные розетки или ограничение заряда, отключённая автоблокировка, обновления iOS/Android по графику, а не автоматически. Человеку рядом со стендом нужно около 15 минут в неделю.

### 4.2 Уровень B — облачная ферма (раз в неделю широкий прогон и по запросу)

| Сервис | Плюсы | Минусы и вопросы |
|---|---|---|
| Selectel «Мобильная ферма» | российский провайдер, 152-ФЗ; ADB, Appium, API, проксирование; поминутно от 1 ₽/мин, от 30 ₽/час, постоянный слот от 20 000 ₽/мес | готового MCP нет, агент работает через ADB/Appium; как автоматизируются iOS-устройства фермы — уточнить у Selectel |
| BrowserStack | официальный MCP-сервер, тысячи реальных устройств и браузеров | прямая оплата из РФ невозможна; агенту нужна лицензия App Automate / Automate (Live-сессии рассчитаны на человека) |
| Mobile Next Cloud | те же инструменты mobile-mcp, что и на стенде | цена и доступность — уточнить |

### 4.3 Уровень C — симуляторы в CI

Уже заложено в `CI_IOS_RU.md` §5 (lane `screenshots`, Maestro): скриншоты на каждый PR. Агент их просматривает и комментирует. Ограничение то же: пуши, CallKit и WebRTC на симуляторе не работают.

### 4.4 Российские мобильные сети

Проблемы с TLS на мобильных сетях РФ (ради которых существует `ssl-totus-tspu.conf`) видны только с настоящей SIM российского оператора. Если стенд стоит не в России, нужен хотя бы один Android с российской SIM в РФ, подключённый к стенду удалённо, либо ручная проверка перед каждым релизом. См. Q-QA2.

## 5. Архитектура

```text
 launchd 06:30 МСК
        │
        ▼
 QA-стенд (Mac mini) ── claude -p "/qa-daily"
   ├─ Playwright MCP ──► браузеры, Electron ──► totus.club · calling · admin · ai
   ├─ mobile-mcp ──────► iPhone / iPad (USB, WebDriverAgent) · Android (ADB)
   ├─ Maestro ─────────► записанные флоу (Android — реальные, iOS — симулятор)
   ├─ HTTP-проверки ───► api · voip · apiv2
   ├─ QA-почта (IMAP) ─► коды входа, письма заказов
   └─ (раз в неделю) ──► Selectel / BrowserStack
        │
        ▼
 репо tosmedia/totus_qa ── сценарии, флоу, отчёты
        │
        ├─► GitHub: issue «QA-отчёт 12.09» + issues по багам (метка qa-bug)
        └─► Slack #totus-qa: сводка в 5 строк + ссылка
                 │
                 ▼
   Владелец: триаж ─► Чат 0 (Оркестратор) ─► профильный чат ─► PR ─► агент перепроверяет
```

### 5.1 Два слоя: записанное ядро + агент

Если каждый день заставлять ИИ проходить весь продукт «глазами», прогон будет долгим, дорогим и нестабильным. Поэтому работа делится на два слоя.

| Слой | Что это | Когда | Цена |
|---|---|---|---|
| **Ядро** | записанные флоу Maestro (YAML) и Playwright-скрипты в `totus_qa` | каждое утро и на каждый PR | почти бесплатно, стабильно |
| **Агент** | Claude сам ходит по продукту: смотрит на экран, ищет странное, проверяет изменённые места, разбирает падения ядра | каждое утро, ограниченное время | токены Claude |

Цикл: агент нашёл баг → воспроизвёл → записал флоу → флоу вошёл в ядро → после исправления флоу зелёный → баг закрыт. Регресс растёт сам с каждым найденным багом.

### 5.2 Инструменты стенда

| Инструмент | Для чего | Примечание |
|---|---|---|
| Claude Code, режим `claude -p`, запуск системным планировщиком (launchd) | «мозг» агента | Desktop scheduled tasks проще для пилота, но срабатывают только при открытом приложении и не спящем компьютере; для постоянного стенда надёжнее launchd |
| Playwright MCP | браузеры и Electron | — |
| mobile-mcp | реальные iPhone (WebDriverAgent + go-ios) и Android (ADB): скриншоты, тапы, дерево доступности | главный инструмент для настоящих iPhone |
| Maestro (встроенный `maestro mcp`) | детерминированные флоу | реальные Android — да; физические iPhone Maestro пока не поддерживает, для них mobile-mcp |
| QA-почта | коды входа, письма | отдельный ящик, не личный |
| GitHub CLI с отдельным токеном | читать коммиты и PR за сутки; писать issues и флоу только в `totus_qa` | права на запись в продуктовые репо нет |
| Slack (webhook или бот) | сводка | канал `#totus-qa` |

Облачные Routines Anthropic не видят USB-устройства стенда. Позже их можно использовать для лёгкого резервного прогона без устройств (health-check сайта и API), если стенд офлайн. Подключённый к claude.ai коннектор Groover (облачный Chromium + почта) годится для разовой проверки страницы прямо из чата, но не для устройств и не для ежедневного прогона.

```text

├── CLAUDE.md                   # роль агента, правила §8, карта поверхностей §3
```

## 6. Ежедневный цикл

| Время, МСК | Шаг | Что делает агент | Оценка до пилота |
|---|---|---|---|
| 06:30 | Health | 6 prod-URL, TLS и сроки сертификатов, коды ответов API, устройства на связи | 5 мин |
| 06:40 | Что изменилось | коммиты и смерженные PR за сутки во всех репо → «фокус дня» | 5 мин |
| 06:50 | Ядро | флоу Maestro / Playwright на всех устройствах уровня A | 30–60 мин |
| 08:00 | Разбор падений | повторяет упавшее, отделяет нестабильное от настоящего | 15 мин |
| 08:15 | Исследование | фокус дня + одна «ротационная» зона (каждая раз в неделю) | 45 мин |
| 09:05 | Пуши | доставка и deep links — после окончания тихих часов 21:00–09:00 | 10 мин |
| 09:15 | Перепроверка | issues с меткой `fixed` → проверить → закрыть или вернуть | 15 мин |
| 09:30 | Отчёт | issue-отчёт в GitHub + сводка в Slack | 5 мин |

**По команде «проверь релиз X»** — smoke за 15–20 минут. **Раз в неделю** (суббота) — широкая матрица на уровне B, сравнение скриншотов с прошлой неделей, доступность, скорость страниц. **Перед релизом в сторы** — полный регресс, плюс ручная проверка звонка человеком (`CI_IOS_RU.md` §6).

## 8. Правила агента на проде (пока нет staging)

| Правило | Почему |
|---|---|
| Не создавать заказы и бронирования | заказ уходит в Level.Travel как настоящий; сквозные сценарии — на staging и тестовом стенде LT `api.staging-prod1.level.travel` |
| Не платить | prod или test у ВТБ — открытый вопрос Q5 |
| В админке и CMS — только чтение | любые правки видны пользователям |
| Не запускать рассылки и «тест» правил напоминаний | пуши уйдут реальным людям |
| Никакой нагрузки и перебора логинов | сработает rate-limit, а мониторинг примет это за атаку |
| Только QA-учётки с пометкой QA в имени | данные тестов отличимы от реальных |
| Не открывать карточки реальных пользователей и заказов; маскировать персональные данные на скриншотах | агент — это ИИ-модель: всё, что он видит на экране, передаётся в Anthropic. Это пересекается с решением «ПДн не передаются в ИИ» и с `LEGAL_DOCS_RU.md` п. 6 и 8 (получатели ПДн, трансграничная передача) |
| Секреты — в Keychain стенда, не в репо и не в отчётах | §3.4 оркестратора |
| Код продукта не менять; писать только в `totus_qa` | §3.5 оркестратора |

## 10. Отчёт и баг-репорт

**Ежедневная сводка:**

```text
QA-отчёт 12.09.2026 · прогон 06:30–09:30 МСК · устройств на связи 6 из 6

Итог: 🟢 сайт · 🟡 iOS · 🟢 Android · 🔴 панель звонков · 🟢 API
Новые баги: 3 (S1 — 1, S3 — 2) → #41, #42, #43
Повторяются: 2 → #35, #38
Исправлено и подтверждено: 1 → #30 закрыт
Не проверено: S9 звонок — iPhone не разблокирован

Фокус дня: totus_WEB#7 (Web Push) — колокольчик в шапке, подписка
Для оркестратора: #41 → Чат 5 (calling-front)
```

**Баг-репорт (issue в `totus_qa`):**

```text
[QA][S2][iOS] Кнопка «Забронировать» перекрыта таб-баром на компактном iPhone

Сборка / устройство: totus_APP 1.4.0 (build 57, TestFlight) · iPhone SE · iOS 26.x
Сценарий: S4, шаг 5
Шаги: 1 … 2 … 3 …
Ожидалось: …
Получено: …
Повторяемость: 3 из 3
Доказательства: скриншот, видео 12 с, лог устройства
Впервые: 12.09.2026, после totus_APP#9
Куда: Чат 3 (totusapp) — по дереву решений оркестратора §4
```

**Шкала серьёзности:** S1 — блокер (не работает ключевой путь), S2 — серьёзный, S3 — заметный, S4 — косметика.

**Дедупликация:** перед созданием issue агент ищет открытые с тем же сценарием и экраном; повтор — комментарий «повторилось», а не новый issue.

**Доска.** Агент доску не трогает: Totus Dev Board — артефакт claude.ai, со стенда её не обновить. После триажа задачу в колонку «Недочёты» переносит оркестратор.

## 13. Риски

| Риск | Что делаем |
|---|---|
| Нестабильные тесты и ложные тревоги | записанное ядро; агент повторяет падение дважды перед заведением бага; метка `flaky` |
| Автоматизация настоящего iPhone хрупкая (WebDriverAgent, туннели, разблокировка) | проверка устройств в начале прогона; «устройство офлайн» — отдельная строка отчёта, не баг |
| Телефоны круглосуточно на зарядке | умные розетки или лимит заряда, осмотр раз в неделю |
| Агент видит прод-данные | правила §8, QA-учётки, маскировка, админка — на staging |
| Растёт расход токенов | лимит ключа, скриншоты по делу, ядро работает без ИИ |
| Интерфейс меняется и ломает флоу | `testID` в коде; агент сам чинит флоу в `totus_qa` |
| Ложное чувство полного покрытия | звук звонков, оплата и ежеквартальный ручной аудит — у человека |
