## 1. Ежечасный чекап (запланированная задача)

- **Название:** «Чекап сайта и приложений Totus Club» (до 16.10 — «Чекап сайта totus.club»).
- **Расписание:** каждый час в :14 (UTC, cron `14 * * * *`).
- **Где работает:** в облаке, все заходы — через коннектор Groover, профиль браузера `checkup`. curl / WebFetch из облака к totus.club получают 403.
- **Одобрение:** автоматическое.
- **Отчёт:** одно сообщение в чате запуска: первая строка «ВСЁ РАБОТАЕТ» или «ЕСТЬ ПРОБЛЕМЫ: …», затем таблицы «Сайт» и «Приложения» (проверка | ✅/⚠️/❌ | детали). При ❌ на сайте — скриншот.
- **Позже:** отправка в Telegram при проблемах.

### Сайт (1–9)

Сквозной путь до бронирования:
1. главная;
2. мобильная главная (iframe 390 px);
3. поиск (Египет по умолчанию);
4. отель (фото, номера, карта);
5. выбор перелёта;
6. окно входа перед бронированием — норма, закрывается крестиком;
7. `api.totus.club/api/home-hero`;
8. /legal и /profile;
9. нет «Application error» / 404 / 500.

Медленно — ⚠️: страница > 10 с, поиск > 30 с, выбор перелёта > 30 с.

## 2. Прогон приложения на устройствах — Maestro (totus_APP #49)

Сценарии лежат в `totus_APP/.maestro`, описание — `.maestro/README_RU.md`.

| Сценарий | Тег | Проверка |
|---|---|---|
| 00 Чистый запуск и онбординг | `fresh` | стирает данные приложения; 4 × «Далее» → «Я согласен»; главная без PIN; вкладки. Выходит из аккаунта, поэтому в ежедневный прогон не входит |
| 01 Запуск и вкладки | `daily` | Москва → Египет; «Заказы»; «Аккаунт» |
| 02 Тур до входа | `daily` | «Найти» → отели → отель → «Выбрать номер» → «Все варианты» → предложение → «Выбрать N ₽» → перелёты → рейс → «Перейти к бронированию» → гость видит «Вход», QA-учётка — бронирование |
| 03 Отель без перелёта | `daily` | тот же путь до формы бронирования, «Цена за проживание» |
| 04 Мила | `auth` | «Totus AI» → «Мила · Тотус клуб», «Онлайн · подбор туров» |
| 05 Чат с поддержкой | `auth` | «Аккаунт» → «Чат с поддержкой» → поле ввода |

### Запуск

`scripts/maestro-checkup.sh` (`--auth`, `--fresh`, `--only ios|android`) проходит по всем устройствам:
- Android — из `adb`;
- iOS — запущенные симуляторы, iPhone / iPad по кабелю или список `IOS_DEVICES`.

Итог — `reports/maestro/<дата_время>/SUMMARY.md`: первая строка «ВСЁ РАБОТАЕТ» / «ЕСТЬ ПРОБЛЕМЫ», дальше таблица «устройство | сценарий | статус | время | причина». Рядом — JUnit, логи и скриншоты.

### Защита от поломок

`scripts/check-maestro-flows.mjs` (в `npm run check`):
- проверяет, что каждая надпись, которую ждут сценарии, есть в `src/`;
- запрещает сценариям ввод текста;
- запрещает нажатия «Войти», «Отправить», оплату, «Выйти», «Удалить», «Позвонить».

### Ограничения

- На устройствах ещё не запускалось. После первого прогона, вероятно, придётся подстроить:
  - кнопку «Выбрать N ₽» (`index: 1`);
  - системные окна.
- Реальные iPhone / iPad Maestro поддерживает не во всех версиях. Надёжный вариант — симуляторы.
- Сценарии `auth` требуют, чтобы на устройстве был выполнен вход QA-учёткой (не личной и не демо-учёткой Apple) с доступом к ИИ.

### Что осталось

1. Слить #49.
2. Подготовить Mac: Maestro + Java 17, adb, Xcode, устройства или симуляторы со сборкой.
3. Войти QA-учёткой на каждом устройстве.
4. Первый прогон `scripts/maestro-checkup.sh --auth` → прислать SUMMARY.md.
5. Запланированная задача на Mac раз в день утром. Её задание подтверждается в разговоре, открытом в приложении Claude на этом Mac. Mac в это время включён и не спит.
