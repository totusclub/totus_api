**Обновлено:** 26.10.2026. История — `claude/JOURNAL_RU.md`, текущее состояние — `claude/STATUS_RU.md`.

Две части:
1. **Ежечасный облачный чекап** — сайт гостем и под QA-аккаунтом, серверы приложений и сторы.
2. **Прогон самого приложения на устройствах** — сценарии Maestro на стенде Mac mini (эмулятор Android, симуляторы iPhone и iPad) раз в день; итог — issue `qa-mac` в totus_APP, ежечасный чекап его показывает.

## 1. Ежечасный чекап (запланированная задача)

- **Название:** «Чекап сайта и приложений Totus Club» (до 16.10 — «Чекап сайта totus.club»).
- **Расписание:** каждый час в :14 (UTC, cron `14 * * * *`).
- **Где работает:** в облаке, все заходы — через коннектор Groover. curl / WebFetch из облака к totus.club получают 403.
- **Профили Groover:**
  - `checkup` — гость;
  - `totus-qa` — QA-аккаунт (с 18.10). Вход через тестовый Яндекс ID (учётка в хранилище Groover, сайт `yandex.ru`) уже выполнен, сессия хранится в профиле, refresh-токен действует до 15.01.2027. Если сессия истекла, чекап пишет ⚠️ и пропускает А2–А5 — заново не входит.
- **Одобрение:** автоматическое.
- **Отчёт:** одно сообщение в чате запуска: первая строка «ВСЁ РАБОТАЕТ» или «ЕСТЬ ПРОБЛЕМЫ: …», затем таблицы «Сайт, гость», «Сайт, QA-аккаунт», «Приложения» и «Прогоны приложения» (проверка | ✅/⚠️/❌ | детали). При ❌ на сайте — скриншот.
- **Позже:** отправка в Telegram при проблемах.

### Сайт (1–9)

Сквозной путь до бронирования:
1. главная;
2. мобильная главная (iframe 390 px);
3. поиск (Египет по умолчанию);
4. отель (фото, номера, карта);
5. выбор перелёта;
6. окно входа перед бронированием — норма, закрывается крестиком;
7. `api.totus.club/api/home-hero`;
8. /legal и /profile;
9. нет «Application error» / 404 / 500.

Медленно — ⚠️: страница > 10 с, поиск > 30 с, выбор перелёта > 30 с.

## 2. Прогон приложения на устройствах — Maestro (totus_APP #49)

Сценарии лежат в `totus_APP/.maestro`, описание — `.maestro/README_RU.md`.

| Сценарий | Тег | Проверка |
|---|---|---|
| 00 Чистый запуск и онбординг | `fresh` | стирает данные приложения; 4 × «Далее» → «Я согласен»; главная без PIN; вкладки. Выходит из аккаунта, поэтому в ежедневный прогон не входит |
| 01 Запуск и вкладки | `daily` | Москва → Египет; «Заказы»; «Аккаунт» |
| 02 Тур до входа | `daily` | «Найти» → отели → отель → «Выбрать номер» → «Все варианты» → предложение → «Выбрать N ₽» → перелёты → рейс → «Перейти к бронированию» → гость видит «Вход», QA-учётка — бронирование |
| 03 Отель без перелёта | `daily` | тот же путь до формы бронирования, «Цена за проживание» |

| 05 Чат с поддержкой | `auth` | «Аккаунт» → «Чат с поддержкой» → поле ввода |

### Запуск

`scripts/maestro-checkup.sh` (`--auth`, `--fresh`, `--only ios|android`) проходит по всем устройствам:
- Android — из `adb`;
- iOS — запущенные симуляторы, iPhone / iPad по кабелю или список `IOS_DEVICES`.

Итог — `reports/maestro/<дата_время>/SUMMARY.md`: первая строка «ВСЁ РАБОТАЕТ» / «ЕСТЬ ПРОБЛЕМЫ», дальше таблица «устройство | сценарий | статус | время | причина». Рядом — JUnit, логи и скриншоты.

### Защита от поломок

`scripts/check-maestro-flows.mjs` (в `npm run check`):
- проверяет, что каждая надпись, которую ждут сценарии, есть в `src/`;
- запрещает сценариям ввод текста;
- запрещает нажатия «Войти», «Отправить», оплату, «Выйти», «Удалить», «Позвонить».

### Стенд на Mac mini (totus_APP #58), с 26.10

Mac mini всегда включён (решение владельца — Mac mini M6; Mac mini 2018 на Intel тоже подойдёт на время, но Xcode новее 26.3 на нём не встанет). Подробно — `scripts/qa-mac/README_RU.md` в totus_APP.

**Установка — одно задание для Claude Code на Mac mini:**
1. Терминал: `curl -fsSL https://claude.ai/install.sh | bash`, новое окно Терминала.
2. `mkdir -p ~/Totus && cd ~/Totus && claude` — вход в Claude через браузер (подписка Pro, Max, Team или Enterprise).
3. Вставить задание из `scripts/qa-mac/README_RU.md` (раздел «Установка»). Claude Code клонирует totus_APP, запускает `scripts/qa-mac/setup.sh --schedule 07:30`, передаёт владельцу команды с паролем (Homebrew, Xcode из App Store, `pmset`, автовход), повторяет до готовности и делает первый прогон.

**Что ставит `setup.sh`:** git, gh, Node 22, Java 17, watchman, cocoapods, Maestro, Android SDK (platform 36, build-tools 36.0.0, NDK, образ Android 15), эмулятор `totus_android` (Pixel 7), симуляторы «Totus iPhone» и «Totus iPad», клон `totus_ai_v2` (пакет Милы), окружение `~/.totus-qa/env`, ежедневная launchd-задача `club.totus.qa-mac`.

**Ежедневный прогон `scripts/qa-mac/run.sh`:**
1. `git pull` totus_APP и totus_ai_v2.
2. Сборки: Android — из Git (`assembleRelease` под процессор Mac), запасной вариант — APK из `~/TotusBuilds`; iOS — из Git, когда появится `ios/totusClubApp.xcodeproj`, **пока** — готовая сборка для симулятора (`*.app.zip`) в `~/TotusBuilds`.
3. По очереди без окон: эмулятор Android → «Totus iPhone» → «Totus iPad»; сценарии `QA_TAGS` (по умолчанию `daily`).
4. `reports/maestro/<дата_время>/SUMMARY.md`: «ВСЁ РАБОТАЕТ» / «ЕСТЬ ПРОБЛЕМЫ» / «ПРОВЕРЕНО ЧАСТИЧНО», у упавшего сценария — шаг, на котором упало; устройство без сборки — «не проверено».
5. При падении — разбор Claude Code (`claude -p`, только чтение файлов) в `TRIAGE.md`: приложение, сервер, Level.Travel, устаревший сценарий или сбой стенда.
6. Issue `qa-mac`: тело — последний прогон; при падении — комментарий с таблицей и разбором (GitHub присылает письмо).

Стенд данные приложения не стирает и ничего в приложение не вводит — вход QA-учёткой сохраняется.

### Ограничения

- Реальные iPhone / iPad Maestro поддерживает не во всех версиях. Стенд работает на симуляторах.
- iOS из Git пока не собирается (в репозитории нет `ios/totusClubApp.xcodeproj`): сборку для симулятора кладут в `~/TotusBuilds` (команда — в README стенда).
- Сценарии `auth` требуют входа QA-учёткой (не личной и не демо-учёткой Apple) с доступом к ИИ на каждом устройстве стенда. Вход в приложении — по почте и коду: вход через Яндекс ID из приложения убран (totus_APP #53).

### Можно ли проверять приложения без включённого компьютера

Приложению нужен работающий iPhone / iPad / Android — настоящий, симулятор или эмулятор. Облачная сессия Claude и Groover этого не дают: Groover управляет только браузером (в том числе удалённым на армянском компьютере, профиль `armenia`), а не нативными приложениями. Отсюда стенд на Mac mini. Дополнительно есть облачный дымовой тест на GitHub Actions (`.maestro/ci/mobile-qa.yml`, issue `qa-mobile`) — короче стенда, macOS-минуты GitHub платные. Облачные фермы (Maestro Cloud, BrowserStack, Firebase Test Lab, Selectel) — платно, из России оплата части недоступна.

### Что осталось

1. Слить #58.
2. На Mac mini — Claude Code по заданию из README; Xcode, пароль в командах из списка.
3. Сборка iOS для симулятора в `~/TotusBuilds` (пока нет `xcodeproj` в Git).
4. Один раз войти QA-учёткой по почте на эмуляторе и симуляторах, `QA_TAGS="daily,auth"` в `~/.totus-qa/env`.
5. Первый прогон → issue `qa-mac` → ежечасный чекап показывает итог (часть 14).
