## 2. Палитра редактора — она попадала на публичный сайт

Самое важное по последствиям. `RichTextEditor` предлагал контент-менеджеру свои наборы цветов, и ими красился текст **страниц сайта** — то есть чужие цвета Tailwind уходили в продакшн через CMS.

Заменено один в один, **литеральными hex**: эти значения попадают в сохранённый HTML, `var()` там не переживёт сохранение.

|---|---|---|
| gray-900 | `#111827` | `#1f1f1f` |
| gray-700 | `#374151` | `#3d3d3d` |
| — | `#fe732e` | без изменений, уже верный |
| sky-600 | `#0284c7` | `#0d77d3` |
| green-600 | `#16a34a` | `#288556` |
| red-600 | `#dc2626` | `#cf3030` |
| violet-600 | `#7c3aed` | `#7e24b2` |

| Подсветка | Было | Стало |
|---|---|---|
| yellow-200 | `#fef08a` | `#facd64` |

Цвет ссылки `#2563eb` → `#0d77d3`. Заголовки внутри редактора переведены из `rem` в пиксели: 28 / 22 / 18 / 16 при line-height 36 / 28 / 24 / 24.

Поле ввода намеренно осталось светлым и в тёмной теме (класс `totus-editor-surface`) — менеджер должен видеть страницу такой, какой её увидит посетитель.

## 3. Принятые решения

1. **Навигация вертикальная**, 260px: разделов будет больше.
2. **Две темы** на каждом экране, выбор хранится в `localStorage`, по умолчанию системная.
3. **В светлой теме область контента белая**, а не серая.
4. **Один стиль заголовка раздела.**
5. **Токены — единственный источник цвета.** Хардкод hex запрещён, исключение только в §2.
6. Структура экранов, тексты и колонки — **как в коде**.
7. Нижняя граница 2px в цвет статуса у карточки заказа не переносилась: плашка статуса и так всё сообщает.

## 5. Реализация в коде — PR #2

Девять коммитов. Логика, состояние, запросы к API, роутинг, пропсы и экспорты не тронуты нигде — правки только по стилям, иконкам и оформительской разметке. Новых зависимостей нет.

### Фундамент

| Файл | Что делает |
|------|-----------|
| `lib/theme.ts` | Единственный источник правды. Токены `t.*` — ссылки на CSS-переменные, поэтому обе темы работают без перерисовки React: меняется только `data-theme` на `<html>`. Плюс `radius`, `text`, `layout` и примитивы `cardStyle`, `inputStyle`, `textareaStyle`, `sectionBox`, `rowStyle`, `button()`, `badge()` |
| `app/globals.css` | Переменные обеих тем вместо палитры Tailwind, фокусные кольца, скроллбар |
| `app/layout.tsx` | Golos Text вместо Inter; тема ставится блокирующим скриптом до первой отрисовки — страница не мигает светлой перед переключением на тёмную |
| `components/ThemeProvider.tsx`, `ThemeToggle.tsx` | Хранение выбора темы, слежение за системной |
| `components/Icon.tsx` | 32 иконки, выгруженные из дизайн-системы (страница «Sigma Icons», вариант Line 20px), цвет через `currentColor` |
| `components/AdminNav.tsx` | Вертикальная панель, внизу переключатель темы, агент и выход |
| `components/PageShell.tsx` | Белый фон, ширина 1280, без градиентов и `backdrop-filter` |

Сдвиг контента под навигацию сделан правилом `body[data-has-nav] .totus-shell` в CSS: флаг ставит `AdminNav` при монтировании. Поэтому экран входа, где навигации нет, остался во всю ширину — и ни одну страницу не пришлось переписывать ради раскладки.

`components/admin/home/styles.ts` стал тонким реэкспортом `lib/theme`, так что секции главной страницы не меняли свои импорты.

### Проверка

**Сборка не прогонялась** — в песочнице, где готовился PR, нет сети ни к npm, ни к Google Fonts. Проверка была статической: полный аудит всех 16 изменённых файлов на сломанные импорты, несуществующие имена иконок, перекрытые токены, оставшийся хардкод цвета и типы аргументов `button()` / `badge()`. Блокирующих сборку дефектов не найдено; один найденный дефект (локальная переменная перекрывала токены типографики в `RichTextEditor`) исправлен отдельным коммитом.

### Что проверить перед мержем

1. **Сборка со шрифтом.** `next/font/google` тянет Golos Text во время сборки — билд-машине нужен доступ к `fonts.googleapis.com`. Если окружение закрытое, шрифт надо переложить в `public/fonts` и подключить через `next/font/local`.
2. Обе темы на каждом экране.
3. Экран входа и второй, staff-логин в разделе «Обращения по заказам» — они рендерятся без навигации.
4. Редактор страницы: вставка текста, ссылки, картинки, палитры цвета и подсветки.

## 6. Замечания не по дизайну

1. **Два разных логина.** Основной вход — под агентом через телефонию (`voip.totus.club/api/web/login`, только роль `agent`). Раздел «Обращения по заказам» требует **отдельного staff-входа** в kedam, со своей формой и своими токенами. Агент, уже вошедший в админку, при переходе в раздел упирается во вторую форму. В коде это прямо оговорено: «Это не логин агента звонков».
2. **JWT к бэкендам не отправляется** — запросы к `totus_API` и voip идут без токена, защита только клиентским `AuthGuard` (риск Б.2/Б.3 в роадмапе).
3. `getAllOrders()` собирает все заказы перебором `/user/orders` по каждому пользователю батчами по 8 — на большой базе будет медленно.
4. `socket.io-client` в зависимостях не используется.
5. `getStatusColor` в `lib/orders-api.ts` после PR нигде не вызывается — можно удалить.
6. На «Главной странице» у всех четырёх соцсетей ссылка не заполнена, то есть иконки в футере сайта никуда не ведут.
