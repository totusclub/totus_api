# Ссылки и чекбоксы под формами — сайт и приложения Totus Club

**Создан:** 14.10.2026 (Cowork, чат «Totus Dev»). Исследование требований + аудит текущего кода totus_WEB (`main`, коммит 088f6a2). Не юридическое заключение.

## Статус

- **14.10.2026** — владелец подтвердил «это можно сделать», макет «Согласия в формах» (https://claude.ai/artifact/KQXdXy6L7qh5MLBrRM4YAx) — «утверждаю». **Реализовано:** [totus_API #38](https://github.com/tosmedia/totus_API/pull/38) (журнал согласий) и [totus_WEB #77](https://github.com/tosmedia/totus_WEB/pull/77) (формы, cookie-баннер, подвал). **Ждём слияния:** API #38 первым (`npm run migrate:consents && pm2 restart api`), затем сайт #77 (`npm run check && npm run build && pm2 restart front`).
- Отличие от макета: [Р] показывается всегда — сайт не знает, есть ли у пользователя согласие на рекламу.
- Решения, заложенные в макет и требующие внимания владельца:
  1. Яндекс Метрика запускается **только после «Принять»** в cookie-баннере → число визитов в Метрике снизится (не учтутся отказавшиеся).
  2. Строка «Реестровый номер турагента» в подвале скрыта, пока номер не внесён в настройку сайта (`NEXT_PUBLIC_TOURAGENT_REGISTRY_NUMBER`).
  3. Бронь отеля без перелёта в карточке заказа называется «Отель в …» вместо «Тур в …».
  4. Новый пользователь Яндекс ID на шаге «Почти готово» обязан отметить согласие; «Отказаться и выйти» — выход из аккаунта.
  5. Сервер в журнале согласий работает в режиме «только записывать»: запросы старых версий приложения без согласий проходят, в лог пишется `[CONSENTS] missing`.
- Состав PR (сделано):

  - **totus_API:** `lib/consents.js` (типы, версии документов, запись), промежуточный обработчик на `POST /api/callback-requests`, `/api/auth/signup`, `/create-package`, `/api/partner-requests` (пишет по `res.finish` при успехе), `POST /api/consents` (strict JWT) для шага Яндекс ID, миграция `scripts/run-consents-migration.js` + `npm run migrate:consents`, проверка `scripts/check-consents.js`, `docs/CONSENTS_API.md`; в `app.js` — 2 строки.

## Правила, из которых всё следует

1. **Согласие на обработку персональных данных — отдельно от любых других документов** (ч. 1 ст. 9 152-ФЗ в ред. 156-ФЗ, с 01.09.2025). Нельзя одной фразой «Нажимая кнопку, вы соглашаетесь с обработкой данных и условиями оферты». Роскомнадзор такую фразу согласием не считает. Штраф по ч. 2 ст. 13.11 КоАП для юрлица — до 700 тыс. ₽.
2. **Согласие — активное действие:** чекбокс, пустой по умолчанию, рядом с кнопкой; ссылка ведёт на **текст согласия** (/consent), а не только на политику.
3. **Ссылка на Политику обработки персональных данных — на каждой странице, где собираются данные** (ч. 2 ст. 18.1 152-ФЗ).
4. **Согласие на рекламу — отдельный необязательный чекбокс** (ст. 18 38-ФЗ). Отказ не должен мешать отправить форму: требовать данные, ненужные для договора, нельзя (п. 15 ч. 2 ст. 16 ЗоЗПП).
5. **Акцепт оферты на тур** — у нас прямо прописан в п. 1.3 Оферты: «проставление отметки о согласии с Офертой» + оплата. Значит, при бронировании тура нужен чекбокс принятия оферты. До заключения договора турист должен иметь доступ к условиям, памятке и сведениям о туроператоре (ст. 10 132-ФЗ, ПП № 551).
6. **Пользовательское соглашение** можно принимать действием («Регистрируясь, вы принимаете…») — это не согласие на обработку, его можно не выносить в отдельный чекбокс, но ссылка обязательна.
7. **Фиксировать каждое согласие на сервере:** кто, когда, какая форма, версия текста, IP. Без журнала доказать согласие при проверке нечем.
8. **Без сокращений** в текстах для пользователей (решение владельца 05.10): «персональных данных», не «ПДн» / «перс. данным».

Основание для данных туристов при бронировании формально — исполнение договора (п. 5 ч. 1 ст. 6 152-ФЗ), но чекбокс согласия всё равно ставим: паспортные данные, данные попутчиков и передача туроператору — так снимаются споры.

## Готовые тексты

**[С] Согласие — обязательный чекбокс, пустой по умолчанию**
> ☐ Я даю [согласие на обработку персональных данных](/consent) и ознакомлен(а) с [Политикой обработки персональных данных](/privacy-policy)

Вариант для бронирования (с данными туристов; для отеля — «гостей»):
> ☐ Я даю [согласие на обработку персональных данных](/consent), в том числе данных туристов, указанных в заказе, — с их согласия, и ознакомлен(а) с [Политикой обработки персональных данных](/privacy-policy)

**[Р] Реклама — необязательный чекбокс, пустой по умолчанию**
> ☐ Хочу получать спецпредложения и новости Totus Club. [Согласие на получение рекламы](/ads-consent)

**[О] Принятие оферты на тур — обязательный чекбокс**
> ☐ Я ознакомлен(а) и принимаю [Оферту о заключении договора о реализации туристского продукта](/tour-offer), условия [изменения, отмены и возврата](/cancellation) и [оплаты](/payment), а также [Памятку туристу](/tourist-memo) и сведения о туроператоре в заказе

**[Б] Принятие условий бронирования отеля без перелёта — обязательный чекбокс**
> ☐ Я ознакомлен(а) и принимаю [Условия бронирования размещения](/hotel-booking), правила отмены выбранного тарифа и условия [оплаты](/payment)

**[У] Пользовательское соглашение — строка текста без чекбокса**
> Регистрируясь, вы принимаете [Пользовательское соглашение](/terms)

**[П] Только ссылка на политику — строка текста без чекбокса**
> [Политика обработки персональных данных](/privacy-policy)

Под заблокированной кнопкой при неотмеченных обязательных чекбоксах: «Отметьте обязательные пункты, чтобы продолжить».

## Что сейчас не так (код totus_WEB, 14.10.2026)

1. **Обратный звонок** — одна строка «Нажимая кнопку, я соглашаюсь… согласно политике… и с условиями оферты»: нет чекбокса, **слова не являются ссылками**, оферта к звонку не относится.
2. **Регистрация и вход** — ни согласия, ни ссылок вообще. Плюс чужой текст «Мы позвоним или отправим сообщение, чтобы подтвердить ваш номер. Применяются стандартные тарифы на сообщения и данные» — код при входе уходит на почту, текст надо убрать.
3. **Бронирование** — «Нажимая на кнопку, вы ознакомлены и соглашаетесь с Политикой по перс. данным и Условиями продажи…»: нет чекбокса, «Политикой» и «Условиями продажи» — это `<span>`, **не ссылки**; документа «Условия продажи» нет (есть Оферта); сокращения «перс.», «потреб.». Не совпадает с п. 1.3 нашей же Оферты (там акцепт — отметка о согласии). Для отеля без перелёта тот же текст и «Тур в …».
4. **Подвал** — на боевом сайте видна заглушка «Реестровый номер турагента: [РТА …]» (правило владельца — никаких заглушек на сайте). Фраза «Информация на сайте не является публичной офертой» противоречит /tour-offer, который и есть публичная оферта.
5. **Cookie-баннер** — «Продолжая пользоваться сайтом, вы даёте согласие…» + «СОГЛАСЕН», без отказа; Яндекс Метрика (`_app.tsx`) запускается на каждой странице до любого выбора.

## Технически

- Общий компонент `ConsentCheckbox` (чекбокс + текст со ссылками, ссылки открываются в новой вкладке), состояние в форме, кнопка неактивна без обязательных отметок.
- Таблица `consents`: `user_id | phone/email`, `type` (`pd`, `ads`, `tour_offer`, `hotel_terms`), `form`, `doc_version`, `ip`, `user_agent`, `created_at`, `revoked_at`. Пишется при успешной отправке формы.
- Если пользователь уже дал [С] при регистрации, при бронировании всё равно ставим [С]-вариант для бронирования — цель другая (данные туристов, передача туроператору).
- [Р] не показывать тем, у кого согласие на рекламу уже есть.
