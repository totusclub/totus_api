## 01.10.2026


**1. Вход через Яндекс на сайте висит на «Завершаем вход…»**
- **Проверено вживую** (Groover, только чтение): totus_API #16 и totus_WEB #14 слиты и развёрнуты; `/start` → 302 на Яндекс; `/callback` и `/exchange` отвечают (не 503).
- **Страница `/auth/yandex`.** Ошибочный ticket → «Ссылка устарела». С подменённым успешным ответом `/exchange` → главная (`needsPhone:false`) или «Почти готово» (`needsPhone:true`, кириллица в JWT). Выложенный чанк совпадает с `main`.
- **Вывод.** Экран загрузки остаётся только пока `POST /exchange` не вернул ответ. У запроса нет тайм-аута (`YandexAuthApi.ts`). Почему он висит у владельца — **не подтверждено**: нужны статус запроса в DevTools или `pm2 ls` / `pm2 logs api | grep -i yandex`.
- **Гипотеза.** Ticket хранится в памяти процесса: при pm2 cluster будет `ticket_invalid` (но это ошибка, а не зависание).
- **Предложено (ждёт «добро»).** totus_WEB: тайм-аут 15 с на обмен + проверка. Если cluster — ticket в БД.
- «Сервис не верифицирован» на экране Яндекса — предупреждение, вход не блокирует; верификацию подаёт владелец на oauth.yandex.ru (нужна опубликованная политика ПД).

**2. Totus Support: нет уведомлений о сообщениях при выключенном экране**
- **Причина (по коду, ограничение из `SUPPORT_APP_STATUS_RU.md`).** Сервер сотрудникам о сообщениях push не шлёт; приложение показывает только локальные уведомления, пока жив сокет. С выключенным экраном ОС усыпляет приложение, сокет рвётся.
- Хаб `lib/notifications` (calling_api_v2 `prod`) шлёт `support_message` только клиенту. В приложении уже есть `@react-native-firebase/messaging` и `@notifee`.
- **Нужно (2 PR, ждёт «добро»):** calling_api_v2 — регистрация FCM-токена устройства сотрудника и push агентам (назначенному, иначе всем) на сообщение клиента без живого сокета; totus_support_app — регистрация токена, фоновый обработчик, канал Android.
- **За владельцем:** `google-services.json` для `club.totus.support`, APNs-ключ в Firebase, App ID с Push.

**3. Админка: заказы грузятся очень медленно**
- **Причина (замер).** `getAllOrders` (Totus_admin `lib/orders-api.ts`): весь список пользователей → `/user/orders` по каждому (пачки по 8). Ответ без сжатия: у одного пользователя 36 заказов = 6,16 МБ (content-length), заголовки за 0,35 с, тело ~34 с. Сервер считает быстро; медленно из-за объёма (полный `package` JSON по каждому заказу) и отсутствия gzip.
- **Предложено (ждёт «добро»):** gzip для JSON (nginx или `compression` в totus_API — владелец/чат API); админский эндпоинт списка заказов с пагинацией и только полями для таблицы; детали заказа — по клику.
- **Попутно (безопасность, известно по аудиту К2, `AUTH_MODE=log`):** `GET api.totus.club/user/orders?user_id=…` и `GET voip.totus.club/api/users` отдают данные без токена.
